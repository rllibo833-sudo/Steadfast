# Contributing to Steadfast

Thanks for considering contributing. Steadfast is meant to make real software work easier for developers and maintainers—not to accumulate features for their own sake.

## Start with a real problem

- **Bug:** report what you tried, what happened, and what you expected.
- **Feature:** describe the developer task that is currently difficult and the smallest useful improvement.
- **Integration or partnership:** explain the workflow, audience, and what a practical collaboration would look like.

Open an issue before substantial work so we can agree on the problem and avoid wasted effort. Small fixes and focused pull requests are welcome.

## You do not need to be a core maintainer

Useful contributions include reproductions, usability feedback, examples, compatibility reports, documentation corrections, tests, integrations, and code. Please be specific about what you observed; no special terminology is required.

## Pull requests

1. Keep each change focused on one user-visible outcome.
2. Explain who benefits and how to try the change.
3. Add or update tests for behavior changes.
4. Run `python -m unittest discover -s tests -v` and relevant CLI checks when possible.
5. Do not include credentials, private repository contents, or unrelated generated files.

If you cannot run the checks locally, say so in the pull request rather than claiming they passed.

## Working together

Be respectful and assume good intent. Ask questions when requirements are unclear. Maintainers may request changes, defer work, or close proposals that do not fit the project's direction; please discuss the problem rather than investing in a large unreviewed implementation.
