# NCM Model Contract (Experimental)

## Purpose

Define the safe boundary between the ecosystem manifest, Steadfast's deterministic graph projection, and a future Next Concept Modeling (NCM) reasoning component.

This document is a proposed engineering contract, not a claim that an NCM reasoning engine exists or that the current adapter performs NCM inference.

## Current state

- `ecosystem/universe.json` is the indexed input.
- `steadfast universe-check` validates the manifest and reports evidence gaps.
- `steadfast universe-model` emits a deterministic graph projection.
- The current projection preserves declared facts and provenance. It does not infer concepts, dependencies, or project status.
- `steadfast universe-infer` provides an experimental purpose-text lexical baseline.
- `steadfast universe-analyze` provides a multi-field lexical discovery graph, candidate project overlaps, and structural graph findings. It is not a semantic NCM engine.
- `steadfast universe-review` validates a human review ledger against the exact SHA-256 model artifact and stable edge IDs. It does not edit the graph or promote candidates.
- No provider credentials or model are configured by default. An opt-in OpenAI-compatible endpoint adapter exists, but it is an LLM-assisted semantic candidate generator, not a validated scientific NCM architecture.

## Epistemic rules

Every model assertion must carry one of these statuses:

| Status | Meaning | May be treated as fact? |
|---|---|---|
| `source_declared` | Directly copied from an indexed source field | Only as a claim made by that source |
| `indexed_reference_not_live_verified` | URI/reference exists in the manifest; target was not checked live | No |
| `manifest_asserted_not_independently_verified` | Relationship was entered in the manifest | No |
| `candidate` | Generated by a future analysis step and awaiting review | No |
| `verified` | A human or trusted verification process attached evidence | Yes, within the evidence scope |
| `rejected` | Reviewed and rejected, with a reason | No |

No model output may silently promote `candidate`, `proposed`, or `unverified` to `verified`. Human review decisions (`accepted`, `rejected`, or `deferred`) are stored in a separate digest-bound ledger; an `accepted` candidate remains epistemically `candidate` until an independent verification process attaches scoped evidence.

## Required model structure

A model document contains:

- `model_version`, `model_type`, and source-manifest identity/version.
- `nodes[]` with stable IDs, kind, label, attributes, and provenance.
- `edges[]` with source/target IDs, relation type, evidence reference, and epistemic status.
- `summary` counts derived from the emitted arrays.
- `semantics` declaring whether inference was performed and whether live source checks occurred.

Stable IDs must be deterministic for identical input. Provenance must identify the manifest field or audit finding that produced each item. A model must not include secrets, credentials, or full source contents.

## Future inference pipeline

A future NCM implementation should be staged and independently testable:

1. **Normalize** — validate the manifest and normalize text without changing source records.
2. **Extract** — propose concepts with exact source spans and provenance.
3. **Relate** — propose typed relations with supporting evidence and an explicit confidence/score definition.
4. **Reconcile** — compare candidate relations with existing declarations and surface conflicts; do not overwrite declarations.
5. **Review** — require human approval or a separately authorized verification process before changing canonical facts.
6. **Export** — emit a versioned model artifact and an auditable change proposal.

The current read-only prototypes implement lexical extraction, relation proposal, endpoint-level reconciliation, explicit graph edges for every well-formed declared manifest relationship, and a canonical SHA-256 digest of the exact source manifest used to build each model artifact. Declared relationships retain their original type and status as provenance attributes and remain epistemically marked as manifest assertions, not independently verified facts. Endpoints that do not resolve to a project, source, or consumer are preserved as unresolved graph nodes rather than silently dropped. `universe-analyze` scans selected descriptive fields across projects, sources, consumers, source references, and inventory notes; extracts normalized tokens and adjacent phrases with exact character spans; creates candidate concept nodes; calculates token-set Jaccard overlap across project text; reconciles candidate project pairs against declared endpoints; and reports unresolved source references, unresolved or malformed declared relationship endpoints, and dangling graph edges. This does not establish semantic agreement, detect logical contradictions, or validate external systems. A matching declared pair is not proof of correctness; an absent pair is not a contradiction. No automatic edits to `universe.json`, project repositories, Notion pages, Supabase projects, device files, MCP configuration, or Hub/dashboard are permitted. Review decisions belong in a separate `ncm-review.schema.json`-conforming sidecar ledger tied to the exact model digest; they do not mutate the model or canonical sources.

## Acceptance criteria for an inference prototype

- Every candidate concept and relation has traceable source evidence.
- Candidate output is distinguishable from declared and verified facts.
- Repeated runs on identical input are deterministic, or any nondeterminism is explicitly recorded.
- Contradictions are reported as review items, not auto-resolved.
- Missing or inaccessible sources remain `unknown`; absence of evidence is not evidence of absence.
- Tests cover deterministic multi-field extraction, exact source spans, Unicode offsets, candidate-only status, threshold filtering, field-level evidence, source-link epistemic status, and graph endpoint integrity. Broader manifest validation remains a separate validator responsibility.
- Existing Steadfast MCP Server, Hub/dashboard, release configuration, and integrations remain unchanged.

## Non-goals

This contract does not prescribe a particular neural architecture, claim equivalence to any research implementation called NCM, or establish that lexical similarity is semantic understanding. Any selected NCM algorithm must be documented and evaluated separately before being described as an NCM engine.


## Read-only source content ingestion (experimental)

`steadfast universe-content` collects bounded snapshots from Notion page blocks, GitHub repository READMEs, and a strict allowlist of local JBF/Termux metadata files. Each captured document includes a stable source identifier, project association, content SHA-256, and read status. The collector uses HTTP GET only, caps document and aggregate size, and does not recursively crawl arbitrary files or Notion child pages.

Supabase content ingestion uses the Data REST API with a publishable key and a required JSON table/column allowlist (`SUPABASE_READ_ALLOWLIST`). Only named columns from named tables are queried, with a 100-row cap per table; no secret/service-role key is accepted. Cloudflare content ingestion fetches explicitly indexed Worker script source with the Workers Scripts GET endpoint and a token scoped to Workers Scripts Read or Workers Content Read-Only. References use `supabase://project/<project-ref>` and `cloudflare://worker/<script-name>`. Missing credentials, unlisted tables, inactive projects, inaccessible scripts, and malformed references remain explicit failures; metadata access is never labelled as content ingestion. Neither reader performs writes or discovers arbitrary tables/workers.

Semantic use of captured text requires both `--allow-remote` and `--allow-source-content-remote`. The second flag is separate because source documents may contain private or proprietary content. Documents are treated as untrusted data, exact evidence quotes are validated against the captured text, and the model artifact records the digest of the source-document snapshot. No source text is sent to a model by the collection command itself.


### Source reader environment configuration

- `SUPABASE_PUBLISHABLE_KEY`: publishable (`sb_publishable_...`) key; do not use `sb_secret_...` or legacy `service_role` credentials.
- `SUPABASE_READ_ALLOWLIST`: JSON array such as `[{"project_ref":"<20-char-ref>","table":"public.notes","columns":["id","title"]}]`.
- `CLOUDFLARE_ACCOUNT_ID`: Cloudflare account identifier.
- `CLOUDFLARE_API_TOKEN`: read-only token with Workers Scripts Read or Workers Content Read-Only.

Keep these as repository Actions secrets or local runtime environment variables. Never store them in the manifest. Collected documents may contain private code or records; keep artifacts out of public commits and require the separate `--allow-source-content-remote` consent before sending content to a model.
