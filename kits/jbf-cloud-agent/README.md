# JBF Cloud Agent

Remote JBF agent hosted on Cloudflare Workers. `jbf agent <task>` sends work to this Worker; the phone is the task entry point and owner approval surface. Inference tries Cloudflare Workers AI, OpenRouter Free, Groq Free, Cerebras Free (`zai-glm-4.7`), NVIDIA NIM Free Endpoint (`nvidia/nemotron-3.5-lightning-30b-a3b`), and Gemini Free (`gemini-3.8-flash`) only after the owner enables free-tier data use. Providers that need API keys are disabled until provisioned. No paid model IDs or credit purchases are used.

Cerebras documents its Free tier at $0 with lower rate limits and an 8,192-token context cap. NVIDIA currently labels the Nemotron endpoint Free; availability and limits can change. Google's Gemini Free tier may use prompts to improve Google products, so JBF keeps it opt-in. Review status with `jbf agent providers`; provider-agent status is included in `jbf agent agents` and the dashboard.

For business and opportunity research prompts, JBF runs three specialist agents: Market Scout (read-only public demand evidence), Unit Economics Analyst (cost, price, contribution, break-even), and Evidence Reviewer (sources, assumptions, approvals). They run only for research requests, use the already configured free inference providers, and do not add account or subscription requirements. Inspect the roster with `jbf agent agents`.

The agent supports GitHub, Cloudflare, and Supabase remote MCP. Explicitly read-only tools may run automatically. Other external calls pause for one exact approval in the local JBF terminal; after approval, the cloud agent resumes the same task. Supabase starts in read-only mode. Sensitive input fields are redacted in approval summaries.

Run `jbf agent providers` to see which provider paths are connected, approval-based, or unavailable without manual setup. JBF reuses the existing GitHub and Cloudflare credentials and can open a dynamic OAuth consent flow for Supabase; it must not ask for pasted API keys, create OAuth apps, or start paid plans. Cloudflare exposes hosting, D1/KV/R2, and Workers AI through the existing account. GitHub Actions is temporary compute, not a persistent VPS. Supabase remains read-only unless a future project-scoped write connection is explicitly approved. Gmail/WhatsApp paths that require manual app registration are skipped. GitHub Models is retired.

Deployment creates a separate Worker named `jbf-cloud-agent` and leaves the existing Steadfast Worker untouched. The workflow supports optional `JBF_CEREBRAS_API_KEY`, `JBF_NVIDIA_API_KEY`, and `JBF_GEMINI_API_KEY` secrets. Gemini additionally requires the Actions variable `JBF_GEMINI_FREE_DATA_APPROVED=true`. Secret values are never logged or committed.

Free quotas and model availability can change. If configured free inference providers fail, the task stops without a paid fallback. The deployment workflow runs code-level checks only; it does not call inference models. Gmail, WhatsApp, and SnapDeploy are not in this first cloud release.

The agent compares product opportunities—including game-studio tools, image/video generation, and other SaaS ideas—by verifiable buyer demand and the fastest free route to revenue. It can build through connected GitHub and Cloudflare tools; writes and deployments are held for owner approval. Owner-provided email and WhatsApp contact values are installed as Worker secrets and used only in owner-approved outreach or a specifically approved public listing. Gmail and WhatsApp sending connectors are not connected.
